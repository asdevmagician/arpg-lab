# Design

## Context

Проект новый; исходников и готовых механик нет. Мотивация описана в proposal.md. Требования находятся в specs/movement-loop/spec.md. Новый игровой цикл и разделение ввода, симуляции и отображения требуют явных технических решений.

## Goals / Non-Goals

**Goals:** чистая тестируемая симуляция, минимальное число зависимостей, однозначная обработка экранных и мировых координат.

**Non-Goals:** игровой движок, физика столкновений, бой, загрузка ассетов из сети, мобильное управление, сглаживание камеры.

## Decisions

1. HTML, CSS, Canvas 2D и ES modules. Canvas подходит для единого поля с бесконечной сеткой; DOM и полноценный движок добавляют ненужную сложность. Портрет — локальный SVG. Node.js обслуживает статические файлы только на loopback.
2. Отдельный модуль симуляции хранит героя, камеру, мировую цель и состояние указателя. Экранная точка преобразуется как `camera + screen - viewport / 2`; масштаб мира — одна единица на CSS-пиксель. Камера обновляется после каждого шага движения.
3. Симуляция идёт фиксированными шагами 1/120 секунды. requestAnimationFrame только накапливает время и рисует. Разовый интервал ограничен 100 мс; после потери фокуса накопитель и ввод сбрасываются. Скорость нормализуется по длине вектора, длина шага ограничивается расстоянием до цели.
4. Первое нажатие сразу задаёт фиксированную цель. До 160 мс она не обновляется: короткий клик не превращается в погоню за движущейся камерой. После порога цель обновляется каждый шаг, а зона покоя 12 пикселей предотвращает дрожание. При отпускании сохраняется последняя рассчитанная цель. Capture указателя обрабатывает отпускание вне Canvas.
5. Сетка и мировые метки рисуются только в видимом диапазоне. Никакая конечная карта не хранится; отрицательные координаты обрабатываются через floor. Размер буфера Canvas учитывает devicePixelRatio, координаты ввода остаются в CSS-пикселях.
6. Node test runner проверяет симуляцию детерминированно. Playwright проверяет реальные события мыши, загрузку, resize, blur и отображение. Тестовый интерфейс доступен только с `?test=1`; обычный пользователь видит краткие подсказки и координаты.

## Risks / Trade-offs

- Порог удержания влияет на ощущение управления: 160 мс — начальное значение для ручной проверки, легко меняется в одном месте.
- Камера без сглаживания подчёркивает подложку: это позволяет отдельно проверить управление до добавления инерции камеры.
- При длительном подвисании симуляция замедляется вместо скачка позиции; для данного локального прототипа предсказуемость важнее компенсации пропущенного времени.
- Автотесты проверяют корректность, но субъективное удобство и читаемость требуют ручного прохождения.
